[Agent Skills](https://agentskills.io) are folders of instructions, scripts, and reference files that teach an AI agent how to do a specific kind of task. Mcpjungle can load skills from disk and serve them to any MCP client through the same `/mcp` endpoint as your other tools.

Use this when you want one shared set of skills for Claude, Cursor, Copilot, and custom agents, instead of copying skill folders onto every machine.

## Skill format

Each skill is a directory that contains a `SKILL.md` file. The file starts with YAML frontmatter followed by markdown instructions:

```text
skills/
└── pdf/
    ├── SKILL.md
    ├── scripts/
    │   └── extract.py
    └── references/
        └── forms.md
```

```markdown
---
name: pdf
description: Extract text and fill forms in PDF files. Use when working with PDFs.
---
# PDF skill

Run `scripts/extract.py <file>` to extract text. For forms, see `references/forms.md`.
```

- `description` is required. The agent uses it to decide when to load the skill.
- `name` defaults to the directory name. It must use lowercase letters, digits, and single hyphens, with at most 64 characters.
- `license`, `compatibility`, `allowed-tools`, and `metadata` are optional and are passed through as-is.

Mcpjungle skips invalid skills and logs a warning for each one.

## Enable skills

Skills are enabled by default. `mcpjungle start` creates a `./skills` directory if needed, and the dashboard **Skills** page includes **+ Add Skill**.

To also load skills that already live on disk, point the server at extra directories:

```bash
mcpjungle start --skills-dir ~/.claude/skills --skills-dir /srv/shared-skills
```

Or use the environment variable:

```bash
export MCPJUNGLE_SKILLS_DIR=~/.claude/skills:/srv/shared-skills
mcpjungle start
```

Each directory can be a single skill, or contain skills at any depth. Mcpjungle ignores hidden subdirectories. If two directories provide a skill with the same name, the first one wins.

Created and installed skills are written to `./skills` unless you set `--skills-install-dir` or `MCPJUNGLE_SKILLS_INSTALL_DIR`. If you pass `--skills-dir` and do not set an install directory, the first skills directory is used.

To turn skills off (no `skills__*` tools and no dashboard install button), start with `--skills-install-dir none` and no `--skills-dir`:

```bash
mcpjungle start --skills-install-dir none
```

Mcpjungle reads the content of `SKILL.md` and bundled files on every request, so edits to existing skills apply immediately. If you add or remove skill folders on disk, click **Reload** on the dashboard's **Skills** page. You don't need to restart the server.

## Create and edit skills

You can write a skill from scratch and edit `SKILL.md` without leaving the dashboard. Created skills are stored in the install directory, the same place GitHub installs go.

1. Open the dashboard and go to **Skills**.
2. Click **+ Add Skill**, keep the **Create** tab, and fill in a name, description, and instructions.
3. Click **Create skill**. MCP clients can use it right away.

To change a skill later, click **Edit** in its row. The name cannot be changed. Bundled files such as scripts and references are left in place.

If the skill was installed from GitHub, saving writes `SKILL.md` on this server. Clicking **Update** reinstalls it from GitHub and overwrites those edits.

## Install skills from GitHub

You can install skills at runtime, similar to `npx skills add`. Installed skills are written to the install directory (`./skills` by default, the first `--skills-dir`, or the directory you set with `--skills-install-dir` / `MCPJUNGLE_SKILLS_INSTALL_DIR`).

If you run Mcpjungle in Docker, mount the install directory as a volume so created and installed skills survive container restarts.

### From the dashboard

1. Open the dashboard and go to **Skills**.
2. Click **+ Add Skill**, switch to **From GitHub**, and enter a source, eg- `anthropics/skills`.
3. Click **Find skills**, select the skills you want, and click **Install**.

Each installed skill shows where it came from. Click **Update** to reinstall it from that source, **Edit** to change `SKILL.md` locally, or **Remove** to delete it. MCP clients see the change right away, without reconnecting.

### From an agent

When [management tools](/guides/management-tools#skills) are enabled, an agent connected to the gateway can create, edit, preview, install, update, and remove skills itself, for example with `mcpjungle__create_skill` or `mcpjungle__install_skills`.

### Supported sources

| Source | Example |
| --- | --- |
| Repository | `owner/repo` |
| Directory in a repository | `owner/repo/path/to/skills` |
| Branch, tag, or commit | `owner/repo@v1.2.0` |
| GitHub URL | `https://github.com/owner/repo/tree/main/skills/pdf` |

Mcpjungle downloads the repository as an archive over HTTPS, so the server doesn't need `git`. It finds every directory that contains a `SKILL.md`, including skills under hidden directories such as `.claude/skills`. To install from private repositories, set the `GITHUB_TOKEN` environment variable on the server.

A skill that comes from a `--skills-dir` directory can't be replaced or removed at runtime. Installing a skill with the same name fails. If a skill with that name is already installed, the dashboard asks you to confirm the replacement.

## What clients see

Skills are served by a built-in server named `skills`. It follows the same `<server-name>__<name>` naming as every other server. Mcpjungle reserves this name while skills are enabled, so you can't register another MCP server called `skills`.

### Tools

Three read-only tools let the agent load skills on demand:

| Tool | Arguments | Returns |
| --- | --- | --- |
| `skills__list_skills` | — | Name and description of every skill. |
| `skills__get_skill` | `name` | Instructions from `SKILL.md`, plus the list of bundled files. |
| `skills__read_skill_file` | `name`, `path` | The text content of a bundled file, eg- `references/forms.md`. |

The description of `skills__get_skill` includes the full skill catalog. An agent can find a matching skill from `tools/list` alone, then load only the skills it needs.

### Prompts

Each skill is also exposed as a prompt named `skills__<skill-name>`, eg- `skills__pdf`. The prompt accepts an optional `task` argument. Use prompts to activate a skill directly from clients that support MCP prompts, such as slash commands in Claude or Cursor.

## Security

- Creating, editing, installing, updating, and removing skills requires an admin user in enterprise mode. In development mode, anyone who can reach the server can manage skills, just like registering MCP servers.
- Downloads are limited to 200 MiB and 20,000 files. Archive entries that are links or that escape the target directory are skipped.
- `skills__read_skill_file` only reads text files inside the skill's own directory. It rejects absolute paths, `..` segments, hidden files, symlinks that point outside the skill, binary files, and files larger than 1 MiB.
- The gateway never runs bundled scripts. Agents can read a script, but it runs in the agent's own environment, if at all.
- In [enterprise mode](/governance/access-control), a client sees and uses skills only if its allow list contains `skills` (or `*`).

## Limitations

- Skills aren't stored in the registry database, so they don't appear on the Tools page and you can't add them to [tool groups](/guides/tool-groups).
- You can't enable or disable individual skills. To hide a skill, remove it.
- Only GitHub sources are supported for installation.
