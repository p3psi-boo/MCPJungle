---
title: "Manage tools and prompts"
description: "List, inspect, enable, and disable the tools and prompts exposed by the MCP servers registered in Mcpjungle."
---

Once an MCP server is registered, Mcpjungle tracks what it exposes and lets you manage that surface area without removing the server itself.

This page covers:

- listing tools and prompts in the dashboard
- checking tool usage (input schema)
- enabling and disabling tools, prompts, and entire servers

MCP clients invoke tools and read prompts through the gateway endpoint. Use the dashboard to inspect and control what those clients can see.

## Tools

Every tool is identified by a canonical name:

```text
<server-name>__<tool-name>
```

See [core concepts](/core-concepts#canonical-names) for more details on names.

### List available tools

Open the **Tools** page in the dashboard. Filter by name or server to find a specific tool.

### Inspect tool usage

Expand a tool row to see its input fields and raw schema.

### Invoke a tool

Tools are invoked by your MCP clients through the gateway. Point the client at `/mcp` (or a [tool group](/guides/tool-groups) endpoint) and ask it to call the canonical tool name.

## Prompts

Mcpjungle supports [MCP Prompts](https://modelcontextprotocol.io/specification/2025-06-18/server/prompts). If a registered server exposes prompts, Mcpjungle registers them alongside that server's tools.

Prompt names follow the same canonical pattern:

```text
<server-name>__<prompt-name>
```

### List prompts

Open the **Prompts** page in the dashboard. Filter by name or server to find a specific prompt.

### Retrieve a prompt with arguments

MCP clients read prompts through the gateway. Expand a prompt row in the dashboard to inspect its arguments before pointing a client at it.

## Enable and disable exposure

Mcpjungle lets you hide tools and prompts from clients without deleting the underlying server registration.

When you disable something:

- it disappears from gateway discovery
- MCP clients cannot call it through Mcpjungle
- you can still inspect it and re-enable it from the dashboard

All tools and prompts are enabled by default when a server is first registered.

### Disable or re-enable a single tool

On the **Tools** page, use **Disable** or **Enable** on the tool row.

### Disable or re-enable an entire server

On the **Servers** page, use **Disable** or **Enable** on the server row. Disabling a server disables all of its tools, prompts and resources in one step.

### Disable or re-enable prompts

On the **Prompts** page, use **Disable** or **Enable** on the prompt row.

## How disabled entities behave

| Context | Behavior                                                                    |
|---|-----------------------------------------------------------------------------|
| Main gateway (`/mcp`) | Disabled tools, prompts and resources are not listed and cannot be called.                 |
| Tool Groups | A disabled tool does not remain available just because a group includes it. |
| Dashboard and HTTP API | Disabled entities can still be listed, inspected, and re-enabled.           |

## Operational notes

- Disabling a server or tool does not remove its registration.
- Delete a server from the **Servers** page if you want to remove it permanently.
